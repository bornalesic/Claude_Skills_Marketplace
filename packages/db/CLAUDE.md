# packages/db — CLAUDE.md

Owner: **W0**, then the **orchestrator**. `src/schema/auth.ts` belongs to **W1**. Spec: `docs/contracts/database.md`.

Drizzle schema, migrations and the database client. No business logic here.

## Structure

```
src/
  index.ts             createDb, Db, schema, withTestDb
  client.ts            postgres.js + drizzle
  schema/
    index.ts           re-exports every table and enum
    auth.ts            Better Auth tables (generated; W1)
    catalog.ts         skill, skill_reference, skill_action, pack, pack_item
    commerce.ts        orders, order_item, entitlement, stripe_event
    usage.ts           mcp_usage
    enums.ts
  testing.ts           withTestDb
migrations/            generated by the orchestrator only
drizzle.config.ts
```

## Rules

- The schema must match `docs/contracts/database.md` exactly: names, types, nullability, defaults, indexes, constraints.
- **Only the orchestrator runs `pnpm db:generate`, and only on `main`.** On a branch, use `pnpm db:push` against your own worktree database.
- Want a schema change in a file you don't own? Request it in your status file with the exact change; it is a contract change.
- `user_id` columns are `text` (Better Auth IDs). App table IDs are `uuid` with `gen_random_uuid()`.
- Keep the client small: one pool per process, `max` configurable, close on shutdown.

## Testing

`withTestDb` gives each test an isolated database state (for example a transaction rolled back at the end, or a fresh schema). `pnpm --filter @upskillzz/db test` checks that the schema applies cleanly and the key constraints (unique entitlement index with `NULLS NOT DISTINCT`, order item check) behave.
